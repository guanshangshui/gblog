# 深入浅出 PyTorch 注一

> 题记：本篇注主要用于解答《深入浅出 PyTorch》的第二节 PyTorch 基础知识，教程来源于 [深入浅出 PyTorch](https://datawhalechina.github.io/thorough-pytorch/%E7%AC%AC%E4%BA%8C%E7%AB%A0/index.html)。仅作为入门参考，实际工业使用相差较大，只作为了解性基础知识。

## 1. PyTorch 的核心对象 tensor（张量）

tensor 是 PyTorch 的核心对象，它是一个多维数组，类似于 NumPy 的 ndarray，但是 tensor 可以在 GPU 上运行，这使得它在深度学习中非常有用。

### 必须点一：tensor 的索引机制

tensor 的索引机制与 NumPy 非常相似，但是也有一些不同之处。PyTorch 支持多种索引方式，包括整数索引、切片索引、布尔索引和高级索引等。但是上述索引，在 PyTorch 当中为了高效计算，统一都是返回一个新的 tensor，但是它们和源索引对象保持同样的地址空间，所以这就导致了，如果需要进行这种索引过后的 tensor 的修改操作，统一需要使用 clone 的技术先复制一份数据再使用。

所以针对这个索引机制，衍生出一种独特的操作 `view()`，它是一个非常重要的函数，它可以改变 tensor 的形状，但是不会改变 tensor 的数据，它返回的是一个新的 tensor。正如其名，view 相当于是"换种视角看待整个 tensor"。但是这里面就涉及到另外一个问题：`view()` 底层是如何做到切换 tensor 的形状并且还可以复用原来的空间的呢？

### 必须点二：神奇的 view()

说到这点，我们不妨可以大胆想象一下，在计算机当中数据保存的形式是怎么样的呢。传统的计算机在缓存当中会提前读出内存当中一整块连续的空间来进行速度优化，并且计算机的寄存器也是为了线性读取来进行优化的，所以在计算机当中，数据的存储形式是线性的。也就是说，不管是二维还是三维的数据，它们在内存当中都是线性存储的。所以 `view()` 函数就是利用了这个特性。

可是如何呈现出不同的形状呢？其实就是通过改变 tensor 的 strides 来实现的。也就是说，`view()` 函数不会 clone 一份原始数据——效率太低了。它们的做法是使用元数据：PyTorch 不改变计算机存储数据的方式，而是通过改变我们读取数据的方式来进行呈现不同的 shape。

比如说：你可以把 tensor 想成一本已经装订好的书，书页本身的内容是固定的，不管你怎么翻，纸上的字都在那里，不会因为你换了读法就重新印一遍。`view()` 做的事情，其实就像是给这本书换一种翻页规则：原来你可能是按 1 页、2 页、3 页这样顺着看，现在它只是在告诉你"每次读几页、从哪里开始读、下一次该跳到哪一页"。

所以它不是复制了一本新书，而是只改了"读书说明书"，也就是 strides 这些元数据；书还是那本书，只是我们看到它的方式变了，于是同一份数据就能被解释成不同的 shape。这也是为什么 view 速度很快，因为它没有搬运数据，只是重新组织了读取路径。

### 必须点三：view() 和 reshape() 的区别

`view()` 和 `reshape()` 都可以改变 tensor 的形状，但是它们有一些不同之处。`view()` 只能在 tensor 是连续的情况下使用，如果 tensor 是非连续的，则需要先使用 `contiguous()` 方法将其变为连续的，然后再使用 `view()`。而 `reshape()` 可以在 tensor 是非连续的情况下直接使用，它会返回一个新的 tensor，并且会尽量复用原来的数据存储空间，但是如果复用不了，也只能 clone 一份然后进行更新。

从这里我们又得涉及到另外一个问题，就是何为连续的 tensor，何为非连续的 tensor。其实就是指在内存当中，连续的 tensor 是指它们在内存当中是线性存储的，而非连续的 tensor 是指它们在内存当中不是线性存储的，也就是说，它们在内存当中是分散存储的。所以 `view()` 函数只能在连续的 tensor 上使用，而 `reshape()` 函数可以在非连续的 tensor 上使用。

最常见的不连续的情况就是在我们创建完 tensor 过后，我们对它进行转置操作。转置操作会改变 tensor 的 strides，比如说创建之前的情况是 `(1,4)`，转置过后变成了 `(4,1)`。虽然转置过后并没有改变数据存储的方式，但是它改变了我们读取数据的方式。正常 `(1,4)` 的情况下面，我们读取下一个元素只需要 +一个元素的字节，读取下一行同列的元素只需要读取这一行的元素的字节即可；但是转置过后，我们读取下一个同行元素就得读取一行的元素的字节，读取下一行的元素反而需要读取一个元素的字节就可以了。

最简单的情况就是，一个 `tensor(1,4)` 下一个是直接的 +1，下一行的是 +4；但是转置过后，下一个是 +4，下一行的是 +1。所以从这个角度来看，我们说转置过后读取的前后顺序不一致，所以这个 tensor 是不连续的。

而 `reshape` 则会判断底层的数据存储方式，如果是连续的，则直接返回一个新的 tensor；如果是非连续的，则会先 clone 将其变为连续的，然后再返回一个新的 tensor。这点正是 `reshape` 和 `view` 使用的关键区别。

### tensor 的核心机制：广播

广播机制是 PyTorch 计算 tensor 当中一个非常重要的机制，经常用于不同大小的 tensor 之间的计算。比如说一个 tensor 的 shape 是 `(3,4)`，另一个 tensor 的 shape 是 `(4,)`，那么在进行加法运算的时候，会自动将 `(4,)` 这个 tensor 扩展为 `(3,4)` 的形状，然后再进行加法运算。这主要是为了解决 tensor 的 shape 不一致的问题，从而实现不同大小的 tensor 之间的计算。

## 2. PyTorch 的另一个核心类 function

function 是 PyTorch 的另一个核心类，最主要的作用是用于记录计算图中的操作。每个 function 对应一个具体的操作，比如加法、乘法、卷积等。

我们知道，在 DL 当中，前向传播和反向传播是模型训练的必经过程。其实微调超参数的任务就是落在了每次计算 loss 和每一层参数的梯度计算上面。可是在前向传播当中，我们是需要计算每一层的输出；而在反向传播当中，我们是逆向需要计算每一层的梯度。我们的每一次前向传播的计算过程出现了计算，但是在反向传播当中，我们该如何来进行梯度的计算呢？

这就涉及到 function 的核心机制，也就是计算图。每一个 function 都会记录它的输入和输出，以及它的梯度函数，从而在反向传播的时候，可以根据计算图来计算每一层的梯度。

所以 tensor 和 function 两个核心类，就在整个模型训练过程当中构建出来一个高效的有向无环图（DAG），这张图完整编码了从最初输入到最终结果的整个计算历史。

## 3. 针对较大模型的训练，PyTorch 的 DP 和 DDP

较为核心的方式是并行训练，并行训练在 PyTorch 当中较为常见的两种思路是 DP 和 DDP。

DP（Data Parallelism）是数据并行，DDP（Distributed Data Parallelism）是分布式并行。

想要训练一个较大的模型，如果说在单卡 GPU 放不下的话，我们比较常见的思路：第一个是拆模型，把每一层的模型分开来进行训练；第二个思路是拆开数据，我们同样的多卡 GPU 里面都保存一份模型，但是数据进行拆开了，每一块 GPU 单独训练一个模型，然后把最后的结果结合到一起然后反向更新每个 GPU 上面的模型参数。

而在我们的 PyTorch 当中，DP 和 DDP 主要针对的是第二种思路，也就是选择拆开数据，然后进行并行训练。

> 注：此处提及到的大模型都是尚且指代单卡 GPU 可以存放的模型，并不是现在深度学习当中那种超大型模型（如 GPT 5.5 这种以 T 为单位的模型）。

在上述 DP 和 DDP 当中，第二种思路使用的较多，原因如下。

### 1）DP 的优缺点

DP 最大的优点就是在于其使用简单，但是缺点却也很明显。对于数据拆分的时候，会存在一定的数据冗余，因为每一块 GPU 上面都会保存一份完整的数据，然后进行训练，然后最后再进行合并，所以会存在一定的数据冗余，导致训练速度较慢。

其次，DP 的训练速度较慢，每一个 GPU 的训练都必须依赖前一个 GPU 的训练结果，所以会存在一定的依赖关系，导致训练速度较慢。

所以不同模型组件在不同的 GPU 上时，GPU 之间的传输就很重要，对于 GPU 之间的通信是一个考验。但是 GPU 的通信在这种密集任务中很难办到，所以这个方式慢慢淡出了视野。

### 2）DDP 的优点和缺点

与其对应，PyTorch 开始转向 DDP 的模式。DDP 是分布式数据训练，主要分为两种情况：单机多卡和多机多卡。

其中，将数据拆开来进行训练，天然就实现了并行化的要求；然后针对于 DP 是一个进程多线程的情况，天然会受到 Python 的 GIL 的干扰，于是 DDP 转变思路切换成多进程之间进行训练。再者针对数据同步的问题做出了优化：DP 需要每个 GPU 都保存一份完整的数据，然后进行训练，然后最后再进行合并，然后把合并计算完成的模型参数同步回去，这就严重拖累了数据同步的情况。而在 DDP 当中，每块 GPU 都可以独立地进行参数的更新，所以在数据同步的时候只需要简单同步一些梯度数据就可以了。

这就是针对 DDP 的优点，但是缺点同样存在：它和 DP 面对的情况是一致的，如果在单卡 GPU 无法存放整个模型的话还是无法正常使用的，并且它的使用相较于 DP 来说也会同时复杂许多。
